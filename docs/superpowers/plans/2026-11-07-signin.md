# Sign-in for the Public Demo — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** One login in front of the whole demo, plus `UI_HOST` so the front end can be opened by the machine's IP. The back end stays on 127.0.0.1.

**Architecture:**
- Three small dependency-free modules:
  - `src/access.js` (accounts file, scrypt);
  - `src/sessions.js` (in-memory sessions and an attempt limiter);
  - `src/auth-gate.js` (Express routes and middleware).
- The gate is mounted in `src/ui-server.js` right after the host guard, before every route and `express.static`.
- The sign-in page is served by the server from `public/signin.html` with its message filled in, so it works without JavaScript.

**Tech Stack:** Node `node:crypto` (`scrypt`, `randomBytes`, `timingSafeEqual`), Express 5. No new packages.

**Spec:** `docs/superpowers/specs/2026-11-07-signin-design.md` (approved 2026-11-07). Mockup: `docs/superpowers/specs/2026-11-07-signin-mockup.html`.

## Global Constraints

- No new dependencies. Plain ESM.
- The nine back-end processes keep `HOST = '127.0.0.1'`. Only the UI server reads `UI_HOST`.
- `UI_HOST` defaults to `127.0.0.1`. A non-loopback `UI_HOST` without `AUTH=on` → startup exits with code 1 and the line `[UI] refusing to listen on <host> without sign-in (set AUTH=on and add an account)`.
- `AUTH` is `on` or `off`. It defaults to `on` when `PUBLIC_ORIGIN` is set or `UI_HOST` is non-loopback, otherwise `off`. `AUTH=on` with no accounts → exit 1.
- Accounts file: `AGENTHUB_ACCESS_FILE`, default `config/access.json` (git-ignored). Shape `{ "users": [{ "username", "salt", "hash" }] }`, hex strings. scrypt N=32768, r=8, p=1, keylen 32, maxmem 64 MiB. Username `/^[a-z0-9._-]{1,32}$/` after lowercasing.
- Sessions:
  - Cookie `ah_session`, HttpOnly, SameSite=Lax, Path=/.
  - `Secure` only when `PUBLIC_ORIGIN` starts with `https://`.
  - Sessions end after 12 h, or after 2 h idle. They are kept in memory only.
- Limiter: 5 failures in 15 min for one username, or for one IP, locks that key for 15 min.
- Copy, exactly as in the mockup:
  - wrong details: “That username and password don't match. Check them and try again.”
  - too many tries: “Too many tries. Wait 15 minutes, then try again.”
  - session ended: “Your session ended. Sign in again to continue.”
  - signed out: “You're signed out.”
- Never log or emit a password, hash, salt, cookie value or session id. The page sets text with `textContent` only. The server escapes everything it fills in.
- The UI's ready line stays `[UI] listening on http://127.0.0.1:<port>` (the tests parse it). When listening wide, a second line: `[UI] also on http://<ip>:<port> (sign-in required)`.
- `/a2a/jsonrpc` and `/.well-known/agent-card.json` skip sign-in, but only for a loopback socket with no `X-Forwarded-For`. Anyone else gets 404.

## Review Focus

1. `next` open redirect (`//evil.com`, `/\evil.com`, `https://…`, `/signin`) → always falls back to `/conversation`.
2. An EventSource stream that gets 401 has no status in the browser → the page must check `/auth/me` on stream error and go to `/signin`.
3. Opening by LAN IP → the host and origin guards must accept the machine's IPv4 addresses and still refuse other Host names (421).
4. An unknown username must take about as long as a wrong password (dummy hash), and get the same message.
5. With `TRUST_PROXY` off, `X-Forwarded-For` must not change the IP used by the limiter.

### Task 1: Accounts — `src/access.js`, `scripts/access.js`

- Produces:
  - `hashPassword(password) -> Promise<{salt, hash}>`
  - `verify(users, username, password) -> Promise<boolean>`, which always runs one scrypt
  - `loadAccess(file) -> users[]`, which throws `AccessError` on an unreadable file or bad JSON
  - `saveAccess(file, users)`, which writes with mode 0600
  - `normalUser(name) -> string | null`
- CLI `node scripts/access.js add|remove|list <name>`:
  - The password comes from a no-echo prompt on a TTY, otherwise from the first line of stdin.
  - Minimum 8 characters. On a TTY it is asked twice.
  - npm scripts `access:add`, `access:remove`, `access:list`.

### Task 3: Gate, page and UI_HOST — `src/auth-gate.js`, `src/local-guard.js`, `src/ui-server.js`, `public/signin.{html,css,js}`

- Produces `createAuthGate({ users, sessions, secure, guardOrigin })` → `{ middleware, routes(app) }`.
- Routes:
  - `GET /signin`
  - `POST /signin` (urlencoded, origin-guarded)
  - `POST /signout` (origin-guarded)
  - `GET /auth/me` → `{ auth: true, username }`; when auth is off the UI answers `{ auth: false }`
- Open without a session: `/signin`, `/signin.css`, `/signin.js`, `/fonts/*`.
- Pages → 302 `/signin?next=`. Anything under `/api` or `/auth` → 401 `{ "error": "sign_in_required" }`.
- Streams are re-checked every 60 s and closed when the session is gone.
- `hostGuard(port, extraHosts = [])` / `sameOriginGuard(port, extraOrigins = [])`. When wide, the UI passes every non-internal IPv4 address from `os.networkInterfaces()` plus the `PUBLIC_ORIGIN` host.
