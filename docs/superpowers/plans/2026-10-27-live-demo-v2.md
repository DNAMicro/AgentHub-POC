# Live demo v2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A presenter-paced, live walkthrough of the finished app where a visible "person" uses the real UI in the left window while the Topology view animates every hop in the right window.

**Architecture:** One `playwright-cli run-code` script (`scripts/demo/live-walkthrough.js`, a single `async (page) => {}` like v1, because run-code takes one function as a string and cannot import). It opens a second page for `/topology`, places both windows side by side over CDP, injects a tiny overlay (step label + cursor dot) with `addInitScript`, and runs scenes made of *moments*; after every moment it waits for a presenter key that reaches Node through `exposeBinding`. A separate small Node command resets the demo's loan file before a talk.

**Tech Stack:** Node ESM, `playwright-cli` 1.59 (`run-code`), Chromium CDP (`Browser.getWindowForTarget`, `Browser.setWindowBounds`), node:test for the reset command.

**Spec:** `docs/superpowers/specs/2026-10-27-live-demo-v2-design.md`

## Global Constraints

- Real UI actions only: mouse moves to the element's centre (`page.mouse.move(x, y, { steps })`), real clicks, typing with `pressSequentially` (never `fill()` for text the person types; the only exception is a native `<input type="date">`, which has no typeable mask in Chromium — click it, then set it via keyboard `type` of `YYYY-MM-DD`, and if that fails, stop the moment rather than inject).
- No slides, no caption boxes, no spotlight overlays. On-screen additions are only: the step label (small, bottom-right corner of each window), the cursor dot, and nothing else.
- Never advance on a timer, except with the rehearsal-only option `auto=<seconds>`.
- Never inject events, call app HTTP endpoints, or change app DOM outside the overlay's own shadow root.
- v1 (`scripts/demo/progression.js`) stays unchanged.
- Fictional data only: Alex Student, alex@example.com.
- Runs against the live stack (`env -u ANTHROPIC_BASE_URL npm run demo:live`); rehearsal only on a **separate stack** with temp data files (see Task 2), never on the user's running demo.
- All servers stay on `127.0.0.1`. Stop processes by port: `kill $(lsof -tiTCP:<port> -sTCP:LISTEN)`.
- Step label text: `Step <n> · <title>`, with titles: 1 `A2A connectivity`, 2 `Browser monitor`, 3 `A2UI form`, 4 `Haiku tutor`, 5 `Routing, skills, scope`, 6 `Workflow forms`, 7 `Hub and topology`, 8 `Generated loan UI`, 9 `Professor`.
- One key press = one meaningful result. Keys: `→` / `PageDown` / `Space` = next moment; `N` = skip the rest of this step; `H` = toggle hold (while held, only `H` is accepted). Keys work with focus in either window.

## Review Focus

1. **The model answers differently than scripted** (words instead of a form, a clarifying question, a decline) → the moment ends on what the app actually did, the label stays, the next key moves on; never a crash or a faked result. (Each scene task: every branch after a model call has a "did it happen?" check.)
2. **A key pressed while the script is still working** (presenter taps twice) → the extra press is not banked; only presses received *after* a moment finished count. (Task 2 test: `waitKey` discards presses that arrived before it started.)
3. **Focus inside a text box** when the presenter presses Space/→ → the key must not type into the app or move the caret as the "next" signal; the listener only acts when the script is waiting, and calls `preventDefault` then. While the script is typing, keys from the presenter are ignored.
4. **The Topology window misses the start of a flow** → the topology page is opened and settled (its SSE `replayed` marker seen, i.e. `#topo` present and 1.5 s idle) before the first moment; it is never navigated during the show.
5. **No renewable loan left** in Step 8 → the moment shows the app's own explanation; the reset command (Task 1) refuses to run while the Library is listening on 41242 (it holds loans in memory).

### Task 2: Walkthrough frame — windows, overlay, keys, human input, rehearsal stack

**Files:**
- Create: `scripts/demo/live-walkthrough.js` (frame + Step 1 scene only)
- Create (scratch, not committed): `<scratchpad>/rehearsal-stack.sh` — starts the five processes live on ports Tutor 51241, Library 51242, Hub 51243, Professor 51244, UI 5444, with the same per-process env `startStack({ professor: true })` in `test/support/harness.js` gives (Hub: `TUTOR_URL`, `LIBRARY_URL`, `PROFESSOR_URL`, `STUDENT_URL`; others: `HUB_URL`, `PORT`/`UI_PORT`) and temp copies of every `data/*.json` via `LOAN_STORE_FILE` (copied from `data/library-loans.before-e2e.json`), `HUB_LESSON_FILE`, `STUDENT_INBOX_FILE`, `PROFESSOR_OUTBOX_FILE`; launched with `env -u ANTHROPIC_BASE_URL` and the `*_MODE=live` values `scripts/start-all.js` uses for `DEMO_MODE=live`. Confirm each startup line says `API host: api.anthropic.com`.

**Interfaces (all inside the run-code function):**
- Options from the opened address's query: `from` (1–9, default 1), `to` (default 9), `fresh` (default on; `0` keeps the conversation), `type` (ms per character, default 55), `auto` (seconds; rehearsal only), `shots` (directory for two screenshots per moment: `NNN-L.png`, `NNN-R.png`).
- `left = page`, `right = await page.context().newPage()` opened at `<origin>/topology`.
- `placeWindows()` — left `{ left: 0, top: 0, width: 1120, height: 1050 }`, right `{ left: 1120, top: 0, width: 800, height: 1050 }` via `newCDPSession(p)` → `Browser.getWindowForTarget` → `Browser.setWindowBounds`.
- Overlay via `context.addInitScript` (survives navigation): shadow-root host `#demo-v2` with the label and a 18 px cursor dot that follows `mousemove`; `setLabel(text)` evaluates on both pages.
- `waitKey() → Promise<'next' | 'skip'>` — a counter-based queue fed by `context.exposeBinding('__demoKey', (src, key) => …)`; presses before the call are discarded; `H` toggles hold; with `auto`, resolves `'next'` after that many seconds.
- `moveTo(locator)`, `click(locator)`, `typeInto(locator, text)` (click then `pressSequentially(text, { delay: TYPE })`), `ask(text) → Locator` (types into `#message`, presses Enter, waits like v1's `settle`, returns the newest `#student-log > li`), `tab(name)` (clicks `#tab-<name>`).
- `moment(name, fn)` — runs `fn`, logs `Step n · name`, saves shots, then `waitKey()`; a thrown error is recorded in `problems`, shown nowhere on screen, and the scene ends at that moment (wait for key, go on with the next step).
- `scenes` — array of `{ n, title, run }`; the main loop sets the label, then calls `run()`; `'skip'` from `waitKey` ends the current scene.
- Returns `{ finished: [n…], problems: [string…] }`.
