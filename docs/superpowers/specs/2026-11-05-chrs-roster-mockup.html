Part 17 — CHRS: the class roster, and who gets each notice

High-fidelity mockup built from the app's own stylesheet, chat markup and Topology code. A new staff-only agent, CHRS, reads student records from its own PeopleSoft database (a demo stand-in, like HR's). Every student shown is fictional.

1

“Show me my class roster”

He types it in the Faculty view. One card answers, laid out like the CSUF Faculty Center Class Roster: the class header, Enrollment Status / Capacity / Enrolled, then the Enrolled Students grid. Look only — the real page’s Notify, Photo, Select All and Printer Friendly controls are left out.

Alex Student and Sam Student (the two demo student agents) are on the roster with 23 more fictional students.

Faculty → Hub (signed staff path) → CHRS → CHRS's AI picks the tool → PeopleSoft student records (MCP).

2

“Notify everyone that …”

He tells the assistant to notify the class in his own words. Code recognizes the request (“notify everyone / all students / the class that / of / about …”), keeps only what comes after it, and sends that to every student on the roster CHRS returns — all 25.

No preview step: it goes out at once, like his other class messages, and the card shows who has it.

Faculty → Hub → CHRS (roster: 25) → one delivery per student, signed by the Hub. CHRS's AI is not asked; the roster lookup is code.

Quiz and cancellation notices also go to all 25

When he publishes a quiz or cancels a class, the Hub asks CHRS who is enrolled — no more fixed list of two.

Only Alex has a student agent online here, so the card leads with a one-line summary and keeps the 25 rows folded.
