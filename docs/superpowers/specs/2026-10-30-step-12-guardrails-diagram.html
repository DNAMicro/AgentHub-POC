A blocked message is not kept in the Hub's history and never comes back as context later. Known limit: the student's own model, on the student's side, sees the text before the Hub does. The guardrail protects the university side.

7. Why it’s built this way: the research behind each step

Each row is one decision in the design, what we copied, and what we deliberately did not copy. Proven facts come from the cited source; the “why” column is our reasoning for this app.

StepWhat we doWhere it comes fromWhy this way (and what we didn’t copy)
Where the check livesInside the Hub, on three hops: student in, replies out, professor postsR1AWS, Microsoft, Google gatewaysEvery message already passes the Hub; checks are chosen per hop by configuration, not by a router per message.
Rules first, gated by a triggerA trigger word wakes a rule; it needs proof (Luhn, SSN ranges) and context (“SSN” nearby) to be sureR2Snort/Suricata fast pattern, Hyperscan R1Purview, Google DLP, MacieCheap work on everything, costly work rarely; proof + context is what keeps false alarms low (the owner’s Presidio experience). We don’t need IDS raw speed — students type a few messages a minute; the point is a bounded worst case.
Rules in a sandboxApproved rule code runs in workerd, one isolate per rule version, no network or files, 50 ms capR4Validation layer R2Snort latency capsRule code is written by an AI, so it must not reach anything. gVisor and Postgres from the deck are not used (deferred / project has no database).
New rulesDescribe → AI writes code + tests → static check → sandbox test (≤2 repairs) → person approves → watch onlyR4Validation layer R3parallel run C2 repairsNo code is generated while a student waits; a person reads every version; watch only proves a rule before it blocks.
The Decision ModelOne Haiku call judges the message against a plain-words policy, all categories at onceR1guard-model studies Aharmlessness screensA general model with a written policy beat small guard models (Llama Guard missed most harmful prompts; Granite over-blocked 25.7%). Anthropic has no separate guard model. A refusal counts as a block.
Hiding the waitThe Decision Model runs at the same time as the routerR2inline AI products Mrouter 2.7 s, Haiku 1.5–2.7 sThe model can’t be made fast, only hidden or made rare. We didn’t copy “watch from the side” (Darktrace, Vectra): the message would already be at the agent.
When time runs outBlock with honest words (8 s cap; 30 s for posts)R2Palo Alto Max Latency, Suricata exception policies OProducts make the timeout outcome a setting; the owner’s rule (nothing reaches a person unchecked) sets ours to block. Matches the project’s no-hidden-fallback rule.
Proof behind every blockThe Decision Model quotes the policy words it used; the Hub checks them word for wordR3grounding check (86.7% → 94.2%) OapprovedEvery block gets a real “because”, at no extra model cost (a string match, like the Library’s evidence check). A bad quote counts as no verdict, so it fails closed. We didn’t copy their second checker model.
SeverityHigh-severity categories block even when the model is unsure; others only when it’s sureR3tuned for serious misses (recall 79.8 → 91.2) OapprovedOne serious miss “eroded confidence significantly”; mild cases can wait for a confident verdict, keeping false alarms low.
What the Decision Model readsWords people write (student messages, Professor Amir’s posts); AI replies get Rules onlyO31 OctAI answers already pass several filters; most risk is human text. Background watch-only on AI replies is the planned test of that assumption.
A not-sure rule finding with no Decision ModelDelivered and logged “would block — not sure”Cbuilder checkBlocking on a guess would bring back false alarms; a sure finding still blocks everywhere.
Verdict cacheReuse a verdict only for the exact same text, policy version and recent turnsCNever reuse a “safe” verdict for a merely similar message.
Test setAI-written violating messages and safe look-alikes; re-run on every change, with planted bad messagesR1HyDE turned around R3accuracy digest, seeded errorsShows over-blocking before going live and keeps people from trusting the machine blindly (34% → 12% in the paper).
TelemetryRule ids, verdicts, timings — never text or matched valuesProject rule (Part 7)Topology and logs can show what happened without spreading the data the guardrail exists to protect.
